# HyPSO-QCO v2 vs related work on the supplied benchmarks

Protocol and reproduction: [README.md](README.md).  Full per-metric tables,
including the 1- and 5-minute GUOQ snapshots, depth, estimated success
probability, runtimes and the deviation of every output:
[REPORT_TABLES.md](REPORT_TABLES.md) (generated by
`python -m qcpso.bench.report_literature`).

Setup:
* Every method optimises the same 10 IBM-Eagle-mapped circuits under the same contract: equivalence on the same physical qubits, and two-qubit gates only on pairs already coupled in the input.
* The anytime optimisers (QUESO, GUOQ, HyPSO-QCO) get the same wall-clock budget of 15 minutes per circuit.
* Qiskit and TKET run to completion.
* One seed per method and circuit.

## 3. Compute-matched comparison (one resynthesis worker)

GUOQ's search is single-threaded.  HyPSO-QCO v2 normally resynthesises
blocks in 4 worker processes.  With **one** worker (same 15-minute budget,
7 circuits up to 17 qubits):

| circuit | GUOQ 15 min: ECR / total | v2, 1 worker: ECR / total | v2, 4 workers: ECR / total |
|---|---|---|---|
| mult_8 | 199 / 1,170 | **166 / 886** | 157 / 805 |
| heisenberg_8 | 326 / 1,597 | **280 / 1,261** | 283 / 1,191 |
| add_17 | 421 / 1,980 | **406 / 1,727** | 389 / 1,647 |
| qae_17 | 428 / **2,057** | **421** / 2,099 | 413 / 1,922 |
| qft_16 | 536 / 2,568 | **531 / 2,244** | 511 / 2,118 |
| hubbard_8 | 1,165 / 4,972 | **975 / 3,914** | 935 / 3,699 |
| hhl_8 | 500 / 2,803 | **326 / 1,764** | 324 / 1,777 |

At matched compute HyPSO-QCO v2 still has fewer ECRs than GUOQ on all 7
circuits.  It has fewer total gates on 6 of 7 (on `qae_17` GUOQ has 2 %
fewer gates).  The margins shrink on `qae_17` and `qft_16` (1–2 % ECRs).
Four workers give a further 0–6 % (on `heisenberg_8` the 1-worker run
happened to be slightly better).

## 4. Ablation: what does the swarm phase contribute?

The pre-registered configuration ("v2") spends 25 % of the budget on the
swarm phase, then refines up to three distinct swarm elites and finally
deepens the best circuit with 5-qubit blocks.  The ablation "memetic only"
evaluates just the strongest elite seed (greedy ECR→CX conversion + TKET
pass + greedy schedule) and gives the whole budget to the memetic phase.
Same 15-minute budget, 4 workers:

| circuit | v2 (swarm 25 % + memetic): ECR / total | memetic only: ECR / total |
|---|---|---|
| mult_8 | 157 / 805 | **156 / 801** |
| heisenberg_8 | **283 / 1,191** | 291 / 1,240 |
| add_17 | 389 / **1,647** | **383** / 1,664 |
| qae_17 | QAE_V2 | QAE_NOSWARM |
| qft_16 | 511 / **2,118** | 511 / 2,176 |
| hubbard_8 | 935 / 3,699 | **901 / 3,312** |
| hhl_8 | 324 / 1,777 | **270 / 1,480** |

(The three large circuits run without a swarm phase in both
configurations, because one decode takes minutes.)

**Honest reading.**  At a 15-minute budget, the swarm phase does **not**
pay for its 25 % of the budget on these circuits.  QAE_SUMMARY
* The run logs show why: the last, *deepening* stage with 4–5-qubit blocks
  gives large late gains (`hhl_8` 315 → 270, `heisenberg_8` 332 → 291).
  With a swarm phase and three elites, this stage gets little or no time.
* The diversity of swarm elites does matter in some cases.  On
  `heisenberg_8` the best of three elites wins, and on `hhl_8` the three
  elites end at 324, 338 and 407.  It just matters less than extra
  resynthesis time.

Consequences:
1. The headline comparison uses the pre-registered configuration.  The
   memetic-only configuration would strengthen it, but it was chosen after
   seeing these results.
2. The advantage over GUOQ, TKET, QUESO and Qiskit comes from the
   connectivity-preserving memetic resynthesis (C9, C10), not from the
   particle swarm.
3. For already-mapped circuits at short budgets, the recommended setting is
   `--resynth-share 1.0` (memetic only).  In the other modes (`cliffordt`,
   `continuous`, `hardware`) the swarm remains the main search engine, as
   the earlier ablations show.

## 6. Where HyPSO-QCO v2 does *not* win, and caveats

* **Physical single-qubit gates.**
  * `heisenberg_8`: QUESO needs 330 against HyPSO-QCO's 425.  QUESO keeps
    all 420 ECRs but applies many single-qubit rewrite rules.  HyPSO-QCO
    still has fewer total gates (1,191 vs 1,217) and far fewer ECRs.
  * `qae_17`: tie with GUOQ at 706; GUOQ's 5-minute snapshot had 687.
* **Numerical exactness.**  The memetic phase and GUOQ use numerical
  synthesis.
  * HyPSO-QCO's outputs deviate from the inputs by 1e-10 to 4e-8.
  * GUOQ's 15-minute `qft_16` output deviates by 5.4e-6.
  * TKET, QUESO and Qiskit are exact.
* **Budgets.**
  * All anytime tools had 15 minutes; GUOQ's paper uses 1 hour.  GUOQ
    was still improving on some circuits (for example `mult_8`: 275 → 231
    → 199 at 1 / 5 / 15 minutes).
  * HyPSO-QCO overran the budget by 2.8 % (`grover_10`) and 5.5 %
    (`hubbard_18`): the deadline is checked between resynthesis blocks.
* **Compute.**  HyPSO-QCO v2 uses 4 resynthesis worker processes.  GUOQ's
  search is single-threaded plus a BQSKit server.  The 1-worker variant
  above addresses this.
* **Seeds.**  One seed per method.  The margins to the best other method
  (3.5–35 % in ECR count) are larger than the seed-to-seed spread
  observed for HyPSO-QCO: the 1-worker runs differ from the 4-worker runs
  by 1–4 %.  Still, no variance estimate is reported.
* **Other related work** could not be run under this contract.
  * **BQSKit O3:** did not finish `mult_8` within 35 minutes, so it is
    not in the table.
  * **PyZX and VOQC** do not preserve connectivity.
  * **Quarl** needs a trained GPU model.
  * **QALM, OAC and POPQC** have no public implementation for this gate set.
  * **Published numbers:** none exist for these exact files, so the tools
    were run here.
* **GUOQ modifications.**  GUOQ was run with a patch that makes its
  resynthesis connectivity-aware (`third_party/`).  Without it, its output
  would not respect the device mapping.  The patch restricts GUOQ, which
  could only lower its ECR reductions.
